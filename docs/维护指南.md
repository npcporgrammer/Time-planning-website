# 日程规划表 · 维护指南

> 适用版本：当前工作区版本（数据模型 `version: 3`）
>
> 配套阅读：[代码逻辑全量解读.md](代码逻辑全量解读.md)

---

## 1. 项目概况

这是一个**完全离线的静态网页**，没有构建步骤、没有依赖、没有服务器、没有网络请求。浏览器直接打开 `index.html` 即可运行。

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面骨架、SVG 图标、所有弹窗和顶部待办抽屉 |
| `styles.css` | 全部样式、主题变量、响应式布局、动画 |
| `app.js` | 全部状态、渲染、交互、存储逻辑 |
| `docs/` | 维护文档目录 |

程序入口是 `index.html` 末尾的 `<script src="app.js" defer></script>`。CSS 通过 `<link rel="stylesheet" href="styles.css">` 加载，不依赖 CDN。

**发布给同学时至少需要带上 `index.html`、`styles.css`、`app.js` 三个文件。** `docs/`、预览图和说明文档可按需附带；不要把个人导出的 JSON 备份误打包进去。

## 2. 启动与验证

### 本地打开

直接双击 `index.html`，推荐 Edge / Chrome / Firefox 的现代版本。

修改代码后，静态文件可能被浏览器缓存：

- 普通刷新可能仍使用旧 JS/CSS；
- 修改后使用 `Ctrl + F5` 强制刷新；
- 或关闭该文件标签页后重新打开。

### 语法检查

本项目没有构建器，可以用 Node 做基础语法检查：

```powershell
node --check app.js
```

CSS 和 HTML 没有构建校验，需要在浏览器中检查布局和控制台。

### 开发时如何避免污染真实数据

应用把数据存在浏览器的 `localStorage` 中。建议：

1. 修改代码前，先用页面菜单「导出备份」保存一份 JSON；
2. 开发测试使用另一个浏览器配置文件、另一个浏览器，或临时导出后清空再恢复；
3. 不要直接编辑浏览器 `leveldb` 目录；
4. 测试完成后，用「导入备份」恢复自己的真实数据。

## 3. 数据存放位置

- **存储键**：`zhouji-weekly-planner-v1`
- **存储方式**：`window.localStorage`
- **作用域**：当前浏览器 + 当前用户配置 + 本地 `file://` 页面 origin
- **不在项目文件夹里**：源文件不包含个人日程数据

Edge 的常见底层目录：

```text
C:\Users\<用户名>\AppData\Local\Microsoft\Edge\User Data\Default\Local Storage\leveldb
```

Chrome：

```text
C:\Users\<用户名>\AppData\Local\Google\Chrome\User Data\Default\Local Storage\leveldb
```

这两个目录由浏览器管理，**不要手工修改**。需要迁移数据时使用页面的「导出备份 / 导入备份」。

> 注意：用 `file://` 直接打开和用 `http://localhost` 打开属于不同 origin，二者的数据不会自动互通。

## 4. 修改地图：想改什么，去哪里找

| 想修改的内容 | 位置 | 备注 |
| --- | --- | --- |
| 浏览器标签标题 | `index.html` 的 `<title>` | 当前为「日程规划表」 |
| 页面主标题 | `index.html` 的 `.heading-line h1` | 当前为「贵在坚持，始于计划」 |
| 整体配色、圆角、字体变量 | `styles.css` 顶部 `:root` | 优先改变量，不要到处改硬编码 |
| 日程块可选颜色 | `app.js` 的 `COLOR_PALETTE` | 同时会影响颜色选择器 |
| 小事纸条自动配色 | `app.js` 的 `TODO_NOTE_COLORS` | 按新增顺序循环取色 |
| 默认时间段 | `app.js` 的 `DEFAULT_SEGMENTS` | 新日期首次出现时使用 |
| 默认行高 / 最小行高 | `app.js` 的 `DEFAULT_ROW_HEIGHT`、`MIN_ROW_HEIGHT` | 行高持久化在时间段数据里；可拖拽高度不设上限 |
| 日期范围 | `app.js` 的 `DATE_MIN` / `DATE_MAX`，以及 HTML 中的日期输入 | 见下方「日期范围」注意事项 |
| 22:00 提醒时间 | `app.js` 的 `isLateEvening`、`scheduleLateReminderCheck` | 当前按 `>= 22` 判断 |
| 对齐吸附距离 | `app.js` 的 `findSnapTarget` 中 `threshold = 9` | 单位是像素 |
| 回收站上限 | `app.js` 的 `pushTrashEntry` 中 `50` | 超出后丢弃最旧记录 |
| 顶栏待办按钮 | `index.html` 的 `#todayButton`、`styles.css` 的 `.today-trigger` | 角标显示当前待办日期的未完成数 |
| 托盘日志描述 | `app.js` 的 `renderPalette`、`openBlockNoteEditor`、`saveBlockNoteDescription` | 编辑器不显示「已完成」按钮；保存会同步所有已放置安排 |
| 长期备忘滚动提示 | `app.js` 的 `renderMemoTicker`、`startMemoTicker`、`pickWeightedMemo` | 固定在页面底部；每 5.6 秒按权重随机切换；打开备忘弹窗时暂停 |
| 长期备忘权重范围 | `app.js` 的 `normalizeMemos`、`syncMemoWeight` | 权重限制为 1—10 的整数 |
| 长期备忘网址校验 | `app.js` 的 `normalizeHttpUrl` | 只接受 http/https，且必须是有效主机名 |

### 修改日期范围的特别注意

当前日期范围在多个地方出现，必须同步修改：

1. `app.js` 的 `DATE_MIN`、`DATE_MAX`；
2. `index.html` 中 `#todoDateInput` 的 `min`、`max`；
3. `app.js` 的 `populateCalendarSelects()` 里硬编码的 2026—2029 年份循环；
4. 说明文档与日历文案中的日期范围说明。

否则会出现日历能翻到、抽屉选不到，或日期被 normalize 过滤掉的问题。

## 5. 数据模型与迁移规则

完整字段说明见[代码逻辑全量解读](代码逻辑全量解读.md#3-数据模型)。维护时需要记住以下约束：

### 5.1 状态是唯一真相

所有界面都从 `state` 渲染：

```text
用户操作 → 修改 state → saveState() → render...()
```

不要只改 DOM 不同步 state；也不要保存后忘记重渲染。

### 5.2 三个必须同步的位置

新增一个顶层状态字段时，至少检查：

1. `createInitialState()`：首次运行时的默认值；
2. `normalizeState(raw)`：读取旧数据 / 导入备份时的兜底值和校验；
3. `clearAllData()`：清空数据后新状态的字段。

如果是日期相关字段，还要检查 `normalizeState` 中的日期范围过滤。

### 5.3 不要破坏已有字段

当前关键结构：

- `days[date].assignments[segmentId]` 是**对象**：
  ```js
  { blockId, note, completed, createdAt }
  ```
  旧版本曾经使用纯 `blockId` 字符串，`normalizeState` 做了兼容迁移。新增逻辑必须按对象处理。
- `blocks` 里的每个模板还保存可选的 `description`（托盘日志描述）；它用于托盘编辑和后续新放置日程的初始日志。
- `todos[date]` 是当日小事数组。
- `trash` 现在只记录从工作台/托盘删除的**日程块模板**（`type: 'block'`），并保存模板 `description`，还原时一并恢复。旧备份里的 `placement` 记录仍可兼容还原，但新操作不再产生这类记录。
- `memos` 是长期备忘数组，每项包含 `title`、`weight`、`linkMode`、`url`、`description`；权重会被限制为 1—10 的整数。
- `profile` 保存昵称、加入日期、打卡日期数组。
- `ui` 只保存 `weekStart`、`selectedDate`；**当日待办所选日期是运行时变量 `todoDate`，刷新后回到今天，不持久化。**

### 5.4 版本号

当前 `version: 3`。版本号主要用于自我标识，不参与自动升级；真正保证兼容的是 `normalizeState` 的容错。若做破坏性结构变更：

1. 提升版本号；
2. 在 `normalizeState` 中兼容旧结构；
3. 用旧备份和旧 localStorage 各测试一次；
4. 更新本文和代码解读文档。

### 5.5 持久化失败

`saveState()` 捕获 localStorage 异常，并把保存状态改为错误。不要吞掉错误后继续假装保存成功。测试时可以在浏览器隐私设置/无痕模式下验证提示。

## 6. 常见改动流程

### 6.1 新增一个功能

1. 在 `index.html` 添加结构（按钮、容器或 `<dialog>`）；
2. 在 `styles.css` 增加组件样式，优先复用变量；
3. 如果新增 DOM id，加入 `cacheElements()` 的 `ids` 数组；
4. 在 `bindEvents()` 用事件委托或直接绑定事件；
5. 在对应 `renderXxx()` 中从 `state` 渲染；
6. 如果影响全页，在 `renderAll()` 中调用；
7. 修改数据时调用 `saveState()`；
8. 测试刷新、导入备份、手机宽度、空状态；
9. 更新 `docs/` 中的维护文档和全量解读。

### 6.2 新增状态字段

按「5.2 三个必须同步的位置」处理。若字段是数组或对象，还要写 normalize 校验，避免导入坏备份后渲染崩溃。

### 6.3 新增弹窗

- 用原生 `<dialog>`，复用 `.dialog`、`.dialog-head`、`.dialog-footer`；
- 关闭按钮加 `data-close-dialog="dialogId"`，通用绑定会自动处理；
- 点击遮罩关闭由 `document.querySelectorAll('dialog')` 的监听处理；
- 若业务上必须阻止按 Esc 或点遮罩关闭，需设计专门例外（参考 `nicknameDialog` 在无昵称时的处理）；
- 不要用 `hidden` 代替 `showModal()`；本项目弹窗用原生 dialog API。

### 6.4 新增颜色

日程块预设颜色改 `COLOR_PALETTE`；小事纸条颜色改 `TODO_NOTE_COLORS`。所有颜色必须经过 `normalizeHex()` 校验后再写入 HTML 内联样式。

### 8.4 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 修改后页面没变化 | 强制刷新 `Ctrl+F5`；确认改的是工作区文件 |
| 数据不显示 | 浏览器是否换了、是否用了不同 origin、是否清空 localStorage |
| 回收站拖入后列表残留 | 检查 `trashBlockDefinition` 末尾的 `renderPalette()` / `renderLibrary()`；表格安排使用 `removePlacementDirect`，不会进入回收站 |
| 托盘拖入占用格没有提示 | 确认拖拽起点在托盘卡片而不是按钮；检查 `updateDropTarget` 的 `is-replace-target` 状态 |
| 拖动不跟手 | 检查 `touch-action`、指针事件是否被 `preventDefault` 干扰、`elementFromPoint` 是否被浮层遮挡 |
| 弹窗打不开 | 检查是否有多个 dialog 已打开；原生 `showModal()` 不能重复调用 |
| 日期越界 | 检查 `DATE_MIN/MAX`、HTML 日期输入、日历循环是否一致 |
| 导入失败 | 检查备份是否是完整 JSON，`blocks` 和 `days` 是否为正确对象 |
| 网址无法保存 | 确认包含有效主机名、没有空格，且协议是 http/https |
| 提示栏不滚动 | 只有一条备忘时本来就不轮播；确认备忘弹窗没有打开 |

### 8.5 恢复干净测试环境

在 DevTools Console 执行（**会清掉当前浏览器的日程数据，务必先导出备份**）：

```js
localStorage.removeItem('zhouji-weekly-planner-v1');
location.reload();
```

## 10. 代码约定与注意事项

1. **状态驱动渲染**：不要直接编辑业务 DOM 当成持久数据。
2. **新增交互先改 state，再 `saveState()`，再 render**。
3. **用户输入必须经过 `esc()`** 再拼接进 HTML。
4. **日期处理使用本地时区**：`parseISODate` 固定用中午 12 点构造，避免时区跨日问题。
5. **ID 必须稳定**：日程块、时间段、小事、回收站记录都用 `uid()`；移动安排时保留原分配对象。
6. **对象的赋值要复制**：拖动已放置日程时用 `{ ...assignment }` 再到目标使用 `makeAssignment`，避免引用被删。
7. **重新渲染范围要克制**：完成状态切换可以只重绘 board/profile/panel；不要无谓重建所有 dialog。
8. **CSS 变量优先**：颜色、圆角、阴影和字体优先用 `:root` 变量。
9. **响应式断点**：1320 / 1120 / 880 / 720 / 480，修改布局时逐档验证。
10. **不要引入网络依赖**：项目承诺纯离线；字体、图标、脚本、图片都必须本地内联或本地文件。
11. **不要直接升级为 ES Module**：当前通过 `file://` 加载，保持普通 script 最稳。
12. **修改拖拽逻辑要测试 `pointer` 事件链**：pointerdown → pointermove → pointerup / pointercancel。

## 11. 已知限制

- 数据只在本机当前浏览器，不做跨设备/跨浏览器同步。
- 页面关闭后不能推送通知；22:00 提醒只在页面打开或重新进入时触发。
- 一个小事只支持纯文字，不支持给小事单独设置时间、优先级或多级标签。
- 周计划的时间格一个区间只放一个日程块，不支持一个格子塞多个。
- 「复用上周」只处理日程安排，不复制自定义小事。
- 日历上的圆点只表示时间轴日程，不表示小事。
- 不支持跨午夜时间段（结束时间必须晚于开始时间）。
- 无撤销栈；表格里的安排拖入回收站或点 × 会直接移除，不进入回收站，也不删除日程块模板。
- 只有工作台/托盘中删除的日程块模板会进入回收站；清空回收站不可恢复。
- 托盘日志描述是“批量同步”语义：保存一次会覆盖该模板所有已放置日程的日志；表格里单独编辑某一条后，不会自动覆盖其它实例，直到下一次从托盘保存。
- 长期备忘的滚动频率是概率性的：权重高更容易被抽中，但不保证固定间隔出现；随机可能连续抽中同一条。
- 长期备忘网址只支持 http/https，且必须是有效主机名；不支持 `file://` 或 `javascript:`。
- 长期备忘最多保存 100 条，且没有回收站，删除后不可恢复。
- localStorage 通常只有几 MB，长期存大量文本时要注意导出备份。

更细的状态字段、函数职责和完整数据流，请阅读[代码逻辑全量解读.md](代码逻辑全量解读.md)。
