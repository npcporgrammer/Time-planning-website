## 1. 整体设计

应用是一个**单页、状态驱动、完全离线**的周计划工具。所有业务逻辑都在 `app.js` 的 IIFE 中，不依赖框架或模块加载器。

核心循环：

```text
用户操作
  ↓
读取/修改 state
  ↓
saveState() 写入 localStorage
  ↓
render...() 从 state 重建界面
```

几个原则：

- `state` 是唯一业务真相，DOM 只是它的投影。
- 界面拆分在少数几个渲染函数中，修改后按影响范围重绘。
- 日程、日期、时间、颜色和 ID 都会在读取时做 normalize 校验。
- 所有用户文本先 `esc()` 再拼入 HTML。
- 静态资源全部在本地；无 fetch、无 CDN、无后端。

## 2. 文件与运行方式

| 文件 | 说明 |
| --- | --- |
| `index.html` | 首屏骨架、内联 SVG 图标、所有 `<dialog>`、当日待办抽屉、顶部按钮 |
| `styles.css` | 设计变量、布局、组件、响应式、动画 |
| `app.js` | 数据模型、初始化、渲染、事件、存储 |
| `docs/` | 维护文档与代码解读 |

浏览器直接打开 `index.html`。`defer` 脚本在 DOM 解析完成后执行，最后调用 `init()`。

`app.js` 被一个 IIFE 包裹：

```js
(() => {
  'use strict';
  // ...
  init();
})();
```

因此函数不会暴露到 `window` 上，DevTools 不能直接调用内部函数；调试通常通过 DOM 操作、localStorage 或临时改代码完成。

## 3. 数据模型

### 3.1 顶层状态

```js
{
  version: 3,
  profile: {...},
  blocks: [...],
  days: {...},
  todos: {...},
  trash: [...],
  memos: [...],
  ui: {...},
  updatedAt: 0
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | 当前数据结构版本，便于识别 |
| `profile` | 昵称、加入日期、打卡日期 |
| `blocks` | 可复用的日程块模板库 |
| `days` | 按日期保存的时间轴与已放置日程 |
| `todos` | 按日期保存的自定义小事 |
| `trash` | 回收站记录，最多 50 条 |
| `memos` | 长期备忘，最多 100 条 |
| `ui` | 上次查看的周和选中日期 |
| `updatedAt` | 最后一次保存时间戳 |

### 3.2 profile

```js
{
  nickname: '小林',
  joinedAt: '2026-10-27',
  checkInDates: ['2026-10-27', '2026-10-28']
}
```

- `nickname` 最大 12 个字符；
- `joinedAt` 为首次设置昵称的日期；
- `checkInDates` 去重、升序；
- 同一天只记录一次；
- 首次打开且未设置昵称时会强制弹出昵称弹窗。

### 3.3 日程块模板 `blocks`

```js
{
  id: 'blk-...',
  title: '深度工作',
  color: '#3f705b',
  description: '这周主要推进项目 A 的调研和初稿。',
  createdAt: 0
}
```

右侧托盘和左下工作台都渲染同一份 `blocks`。删除模板时，所有引用它的已放置安排会一并处理。

`description` 是托盘日志描述：

- 在托盘卡片右侧点铅笔按钮编辑；
- 保存后会写入该模板的所有已放置 assignment.note；
- 新拖入格子的日程会以它作为初始 `note`；
- 表格详情里修改某一条日志时，也会同步更新对应模板的 `description`，但不会自动覆盖其它已放置实例；
- 再次从托盘保存时，会将所有实例统一。

托盘日志弹窗是 `#blockNoteDialog`，没有「已完成」按钮；完成状态只属于已放置的具体日程，操作入口仍然是表格里的详情弹窗。

### 3.4 每日数据 `days`

```js
days['2026-10-30'] = {
  segments: [
    {
      id: 'seg-...',
      start: '08:00',
      end: '09:30',
      height: 70
    }
  ],
  assignments: {
    'seg-...': {
      blockId: 'blk-...',
      note: '读《深度工作》第二章。',
      completed: false,
      createdAt: 0
    }
  }
}
```

关键点：

- `segments` 是这一日**独立**的时间轴，按开始时间升序；
- 每天的时间段数量、起止时间、视觉高度都可以不同；
- `assignments` 以 `segmentId` 为键，因此一个格子最多一个日程；
- `note` 是详情日志；
- `completed` 同时驱动周计划灰色覆盖层和当日待办完成统计；
- 旧版本曾经把 `assignments[segmentId]` 存成纯 `blockId` 字符串，`normalizeState` 会自动迁移成对象。

### 3.5 小事 `todos`

```js
todos['2026-10-30'] = [
  {
    id: 'todo-...',
    text: '给老师发邮件',
    completed: false,
    color: '#f4e2ae',
    createdAt: 0
  }
]
```

- 纯文字，最大 80 字；
- 颜色按新增顺序从 `TODO_NOTE_COLORS` 中自动分配并持久化；
- 删除是直接删除，不进回收站；
- 首页顶栏按钮的角标统计的是当前 `todoDate`（默认今天）的**未完成**数；
- 刷新页面后 `todoDate` 会回到真实今天，但已写入 `todos` 的内容不丢。

### 3.6 回收站 `trash`

回收站有两种记录：

```js
// 整个日程块（可能带有多个已放置安排）
{
  id: 'trash-...',
  type: 'block',
  title: '深度工作',
  color: '#3f705b',
  description: '回收前的托盘日志描述',
  blockId: 'blk-...',
  placements: [
    { date, segmentId, start, end, note, completed }
  ],
  deletedAt: 0
}

// 只回收一次已放置安排
{
  id: 'trash-...',
  type: 'placement',
  title: '深度工作',
  color: '#3f705b',
  description: '回收前的托盘日志描述',
  blockId: 'blk-...',
  placements: [ /* 单条 */ ],
  deletedAt: 0
}
```

- 删除整个模板：`type: 'block'`；
- 从格子里移除一次安排：`type: 'placement'`；
- 记录会保存模板 `description`，还原模板时一并恢复；
- 还原时优先按 `segmentId` 找回原时间格，找不到再按开始/结束时间匹配；
- 目标格已有安排则跳过；
- 模板可能已不存在，`ensureTrashBlock` 会从回收记录中重建；
- 超出 50 条时丢弃最旧记录。

### 3.7 ui

```js
{
  weekStart: '2026-10-26',
  selectedDate: '2026-10-30'
}
```

`weekStart` 始终是一周周一。当日待办面板选择的日期不在 state 中，而是运行时变量 `todoDate`。

### 3.8 长期备忘 `memos`

```js
[
  {
    id: 'memo-...',
    title: '蓝桥杯备赛',
    weight: 8,
    linkMode: false,
    url: '',
    description: '每天 2 小时算法训练，周日做一套模拟赛。',
    createdAt: 0,
    updatedAt: 0
  }
]
```

- `title` 最长 80 字；`description` 最长 2000 字；
- `weight` 是 1—10 的整数，越大在滚动提示中出现概率越高；
- `linkMode=true` 时是网址备忘，`url` 只允许 http/https 且有有效主机名；
- `linkMode=false` 时是纯文本备忘，`description` 是详情内容；
- 最多保留 100 条；
- `currentMemoId` 是运行时变量，不在 state 中；刷新后重新选择。

## 4. 初始化与持久化

### 4.1 `init()` 顺序

1. `cacheElements()`：把所有用到的 DOM id 缓存到 `els`；
2. `populateCalendarSelects()`：生成 2026—2029 年份和 12 个月的下拉；
3. `renderColorSwatches()`：生成日程块颜色按钮；
4. `bindEvents()`：绑定所有事件；
5. `loadState()`：读 localStorage 并 normalize；
6. `todoDate = 今天的 ISO（若超出范围则 DATE_MIN）`；
7. `renderAll()`：首屏渲染；
8. `renderMemoTicker()`：渲染长期备忘提示栏；
9. `startMemoTicker()`：有至少两条备忘时启动加权轮播；
10. `updateSaveStatus('saved')`；
11. 首次运行立即保存 seed state；
12. 已有昵称则自动补打卡、保存并延迟检查 22:00 提醒；
13. 没有昵称则延迟弹出昵称对话框；
14. 启动 22:00 定时检查；
15. 如果读取数据有异常，显示警告 toast。

### 4.2 `loadState()`

- localStorage 不存在：创建初始状态，`firstRun: true`；
- localStorage 读取异常：返回初始状态并提示浏览器限制；
- JSON 解析或 normalize 异常：返回新状态并提示；
- 正常：返回 normalize 后的状态。

### 4.3 `saveState()`

- 每次业务变更后立即写入；
- 更新 `updatedAt`；
- 更新「已保存 HH:mm」状态；
- 写入失败时把状态改为「未能保存到本机」，并提示导出备份；
- 不做异步/防抖，因为数据量很小，保证关闭页面前已落盘。

### 4.4 旧数据兼容

`normalizeState(raw)` 做这些工作：

- 只保留 2026-01-01—2029-12-31 范围内的日期；
- 校验 block、profile、todos、trash；
- 校正 `weekStart` 为周一并夹在允许范围内；
- 校正 `selectedDate`；
- 将字符串 assignment 迁移为对象；
- 丢弃指向不存在模板的 assignment；
- 合并重复 ID；
- 时间轴按开始时间排序，去掉重叠段；
- 高度夹在 38—240px。
- 旧数据没有 `todos` / `trash` / `profile` 时补默认空值。

## 5. 基础工具函数

### 5.1 日期

- `parseISODate(iso)`：把 `YYYY-MM-DD` 解析为本地中午 12 点的 Date，避免时区跨日；
- `toISODate(date)`：本地日期转 ISO；
- `addDays(date, n)`：加减天数；
- `mondayOf(date)`：返回该日期所在周的周一；
- `getWeekDates(weekStart)`：返回 7 个日期；
- `isoWeekNumber(iso)`：计算 ISO 周数；
- `formatRange(startISO)`：周范围中文文案；
- `formatChineseDate(iso)`：`2026年10月30日 · 周五`；
- `weekdayIndexOf(iso)`：周一为 0。

### 5.2 时间

- `normalizeTime(value)`：把 `8:00` 规整为 `08:00`，非法返回 null；
- `timeToMinutes(time)`：转为分钟数；
- `minutesToTime(n)`：分钟数转 `HH:mm`（夹在 0—1439）；
- `durationLabel(start, end)`：`90 分钟`。

### 5.3 颜色与 HTML 安全

- `normalizeHex`：校验六位十六进制颜色；
- `hexToRgb`、`blockColorVariables`：生成日程块 CSS 变量；
- `esc()`：转义 `& < > " '`，所有用户标题、昵称、小事、aria/title 都必须走它；
- `setStyleSafe`：只用于颜色等已知安全值的 CSS 变量。

### 5.4 其它

- `uid(prefix)`：优先 `crypto.randomUUID()`，否则时间戳 + 随机串；
- `clamp`：数值夹取。

## 6. 渲染系统

### 6.1 `renderAll()`

当前顺序：

```text
renderHeader()
renderProfile()
renderBoard()
renderPalette()
renderLibrary()
renderTrash()
renderTodayTrigger()
if (todayPanelOpen) renderTodayPanel()
updateBoardHeights()
```

这个顺序避免顶部、个人卡片、周计划、托盘、工作台、回收站和待办角标出现状态不一致。

长期备忘提示栏**不在** `renderAll()` 里：它在初始化、导入、清空、备忘保存/删除后单独调用 `renderMemoTicker()` 和 `startMemoTicker()`。这样切换周、完成日程等普通重绘不会重置正在进行的轮播。

### 6.2 `renderHeader()`

- 周范围、周数、本周安排数；
- 上一周/下一周禁用状态；
- 「复用上周」是否可用；
- 本周按钮文案（本周 / 回到本周）；
- 超出日期范围时的提示。

周数统计的是**时间轴安排**，不包含自定义小事和已完成外的特殊计数。

### 6.3 `renderBoard()` / `renderDayCard()`

- `getWeekDates` 取出 7 天；
- 范围内日期调用 `ensureDay`（首次创建默认时间轴）；
- 计算所有日期中最大的 body 高度（最小 240px），让各列卡片底部对齐；
- 对每天生成 `.day-card`：
  - 头部日期、今天状态、选中状态、安排数量、时钟按钮；
  - body 内为每个时间段生成 `.time-row`；
- 范围外日期渲染禁用说明，不生成槽位。

### 6.4 `renderTimeRow()`

每个时间行包含：

- 左侧时间标签；
- `.slot` 槽位，带 `data-date` / `data-segment-id`；
- 有安排时渲染 `.scheduled-block`；
- 行底部 `.row-resizer` 用于拖拽高度。

`renderScheduledBlock` 会附加：

- 模板颜色 CSS 变量；
- `is-completed`（灰色覆盖 + 划线）；
- `has-note`（用于样式微调）；
- 删除按钮；
- `data-source-date` / `data-source-segment`，供拖拽读取。

### 6.5 `renderPalette()` / `renderLibrary()`

两处都渲染 `state.blocks`，但用途不同：

- 右侧托盘：可拖拽卡片，显示「已安排 N 次」；
- 左下工作台：带编辑/删除按钮的 chips。

任何模板变化都会更新这两个区域。回收站删除模板后会额外再调用这两个渲染函数，避免界面残留。

### 6.6 `renderProfile()`

- 左上角头像首字、打卡状态点；
- 问候语 `hi！昵称，我们要计划什么。`；
- 打卡天数、连续打卡；
- **全部待办 = 日程安排 + 自定义小事**；
- **已完成 = 已完成日程 + 已完成小事**；
- 个人信息弹窗的头像、昵称、加入日期、今日打卡状态。

注意：统计是**所有日期累计**，并不只当前查看周。

### 6.7 `renderTrash()`

- 回收站数量；
- 每条记录显示标题、类型、包含安排数或日期时间；
- 渲染「还原」按钮；
- 空状态；
- 清空按钮的显隐。

### 6.8 `renderTodayTrigger()` / `renderTodayPanel()`

- 顶栏按钮的未完成角标；
- 待办抽屉的日期、进度、日程列表、小事纸条；
- 日程列表按开始时间排序；
- 小事按创建顺序展示；
- 日程和小事都支持从列表勾选；
- 进度条按 完成数 / 总数 计算。

### 6.9 `updateBoardHeights()`

在行高调整时同步所有列的最小高度，避免某一列比其它列短时出现参差的底部空白。

## 7. 每周时间板

### 7.1 独立时间轴

七列日期都指向各自的 `days[date].segments`，所以：

- 每天可以有不同数量的时间段；
- 每天可以有不同的起止时间；
- 每天的行高可独立调整；
- 拖动一天的行不会改变其它日期的数据。

但界面会让所有日卡片的 body 至少和最高列一样高，避免版面参差。

### 7.2 日期范围

- `DATE_MIN = '2026-01-01'`
- `DATE_MAX = '2029-12-31'`
- `MIN_WEEK_START` 为 2025-12-29
- `MAX_WEEK_START` 为 2029-12-31

周视图可能跨年，超出范围的日期会变为 `.is-outside`，槽位不可用。

### 7.3 周切换

- `navigateWeek(offset)` 保持当前选中的星期几；
- `setWeek()` 将周一夹到允许范围，重建视图并保存；
- `goToToday()` 回到今天所在周。

### 7.4 独立时间轴的创建

`ensureDay(date)` 懒创建：

```js
{
  segments: makeDefaultSegments(),
  assignments: {}
}
```

默认 6 个时间段：

```text
08:00—09:30
09:30—11:00
11:00—12:30
13:30—15:30
15:30—17:30
19:00—21:00
```

## 8. 日程块工作台

### 8.1 新建

`handleBlockSubmit`：

- 读取输入和所选颜色；
- 非空校验；
- 新建 `{id,title,color,description:'',createdAt}`；
- 写入 `state.blocks`；
- 自动选择下一个未使用颜色；
- 保存并重渲染托盘、工作台、周计划、头部。

### 8.2 编辑

`startEditingBlock` 把模板数据回填到表单，提交时按 `editingBlockId` 更新标题和颜色。所有已放置实例通过 `blockId` 自动反映新颜色/标题。

### 8.3 删除

`deleteBlockWithConfirm` 先提示：

- 删除会连同所有已放置安排一起移入回收站；
- 确认后调用 `trashBlockDefinition`。

### 8.4 删除的三种入口

| 操作 | 结果 |
| --- | --- |
| 点击工作台 chip 的删除 | 确认后整个模板 + 所有安排进入回收站 |
| 从右侧托盘拖入回收站 | 整个模板 + 所有安排进入回收站 |
| 从格子拖入回收站（最后一项） | 模板 + 该项安排进入回收站 |
| 从格子拖入回收站（还有其它安排） | 只回收本次安排，模板保留并提示 |

最后一项的行为是专门为避免托盘/工作台残留而加的。

### 8.5 托盘日志描述编辑

托盘卡片渲染时会附加一个铅笔按钮：

```html
<button data-edit-block-note="blockId">…</button>
```

事件流：

1. `bindEvents` 在 `paletteList` 上委托 click；
2. 命中 `[data-edit-block-note]` 时调用 `openBlockNoteEditor(blockId)`；
3. `getBlockPlacements` 收集该模板的所有已放置实例；
4. 如果实例日志完全一致，优先用这条日志；否则使用 `block.description`；再次退化为第一条日志；
5. 弹窗 `#blockNoteDialog` 显示标题、放置数量、当前描述和同步提示；
6. 点击保存调用 `saveBlockNoteDescription`：
   - 写入 `block.description`；
   - 遍历 `state.days`，把该模板所有 assignment.note 改成同一段文本；
   - 保存、关闭、`renderAll()`；
   - toast 显示同步了多少项。
7. 有多个不同日志时会提示“保存后会统一”；
8. 没有放置实例时提示“下次拖入会自动带上”。

弹窗只有「取消 / 保存描述」，**没有完成状态按钮**。完成状态只针对已放置的具体日程。

新增放置的初始化：

```js
const assignmentData = sourceType === 'palette'
  ? { note: block.description || '' }
  : (sourceAssignment || {});
```

因此带描述的托盘模板拖入格子后，双击详情立刻能看到同一段描述。

表格详情的反向更新：

- `queueDetailSave` / `flushDetailSave` 修改当前 assignment.note 时，也把同一个值写到模板 `description`；
- 关闭详情后 `renderPalette()` 刷新托盘的「已写日志」标记；
- 但不会自动把所有其它实例一起改掉，需再次从托盘保存以实现统一。

## 9. 拖拽引擎

拖拽不是 HTML5 drag，而是 Pointer Events + 自定义浮层。

### 9.1 启动

`handleDocumentPointerDown`：

1. 排除鼠标右键、已打开 dialog 的场景；
2. 判断起点是 `.palette-card` 还是 `.scheduled-block`；
3. 起点若在按钮内则不启动（删除按钮可正常点击）；
4. 记录模板、来源、坐标、来源日期/时间段；
5. 监听 `pointermove` / `pointerup` / `pointercancel`；
6. 移动超过 5px 才真正进入拖拽。

### 9.2 拖拽状态 `dragState`

包含：

- `block`、`sourceType`（palette / scheduled）；
- 来源日期和时间段；
- 起点元素、起始坐标、最后坐标；
- 是否已真正开始；
- 当前高亮槽位或回收站；
- 是否有效目标。

### 9.3 视觉反馈

- `.drag-ghost` 跟随指针，显示模板名和当前提示；
- 从托盘拖拽时源卡片淡出；
- 从格子拖拽时源安排淡出；
- 有效槽位高亮 `.is-drop-target`；
- 已占用槽位显示 `.is-invalid` 和「已占用」；
- 回收站高亮 `.is-trash-hover`；
- 页面下方出现悬浮回收站，松手即可回收。

### 9.4 放置逻辑

`handleDragEnd`：

1. `elementFromPoint` 找到落点；
2. 优先判断是否在 `[data-recycle-drop]`；
3. 否则判断是否在 `.slot`；
4. 槽位已占用则拒绝并 shake；
5. 从格子移动时复制原 assignment 的 `note` / `completed`；
6. 写入目标槽位；
7. 保存并重渲染；
8. 清理浮层、高亮和监听。

### 9.5 回收站放置

- 从托盘拖入：`trashBlockDefinition`；
- 从格子拖入且这是最后一个安排：`trashBlockDefinition`；
- 从格子拖入且还有其它安排：`trashPlacement`，提示模板仍保留。

### 9.6 自动滚动

`autoScrollDuringDrag` 在指针接近视口底部或周计划左右边缘时滚动，方便把日程拖到远处日期。

### 9.7 清理

`cleanupDrag` 会移除所有拖拽类、隐藏 ghost 和悬浮回收站、移除 window 监听并清空 `dragState`。异常中断（pointercancel）也走同一清理。

## 10. 行高调整与对齐顿挫

### 10.1 开始

`handleBoardPointerDown` 只处理 `.row-resizer`：

- 记录日期、时间段、行、起始 Y、起始高度；
- 缓存当前行顶部位置；
- 缓存**其它日期**所有 `.time-row` 的底部坐标和结束时间标签；
- 进入 resizing 状态。

### 10.2 移动

`handleResizeMove`：

- 原始高度 = 起始高度 + 指针位移；
- 夹在 38—240px；
- 计算候选底边坐标；
- 在 9px 阈值内查找最近的其它日期行底边；
- 命中则吸附到该底边，显示横向参考线；
- 文案提示「已对齐 N 个时段 · 时间」；
- 通过 `navigator.vibrate(8)`（支持的设备）和 CSS `snap-pulse` 模拟顿挫感；
- 记录上一次吸附位置，避免同一位置反复触发。

### 10.3 结束

- `pointerup` 保存高度、隐藏参考线、清理监听；
- `pointercancel` 同样清理并保存；
- 双击 resizer 恢复 70px 默认高度。

吸附范围只考虑其它日期的行底边，所以是为了“不同日期的同一时间段对齐”，不是改变其它列。

## 11. 日程详情与完成状态

### 11.1 打开

`handleBoardDoubleClick` 检测 `.scheduled-block`，调用 `openScheduleDetail(date, segmentId)`：

- 找到 assignment、block 和时间段；
- 填充标题、日期、时间、颜色点；
- 把日志写入 textarea；
- 打开原生 `<dialog>`；
- 聚焦 textarea。

### 11.2 日志保存

- `input` 事件触发 `queueDetailSave`；
- 立即把文本写入 assignment.note；
- 280ms 防抖保存；
- 弹窗关闭时 `flushDetailSave` 强制保存；
- 如果关闭时仍有未保存更改，会重渲染 board 以更新「有记录」状态。

### 11.3 完成状态

`toggleDetailComplete`：

- 切换 `assignment.completed`；
- 保存；
- 更新详情按钮文字和状态；
- 重渲染 board、profile、顶栏角标；
- 如果当日待办抽屉开着，同步刷新。

周计划上的表现：

- `.scheduled-block.is-completed`；
- 背景变淡灰；
- 标题划线；
- 右下出现小对勾；
- 颜色条变灰。

再次点击完成按钮可撤销。

### 11.4 两个日志入口的区别

| 入口 | 数据对象 | 是否显示完成按钮 | 行为 |
| --- | --- | --- | --- |
| 双击格子里的日程 | 单个 assignment.note | 有 | 只编辑这一条；同时更新模板 description |
| 托盘卡片的铅笔按钮 | 模板 description + 所有 assignment.note | **没有** | 保存后批量同步所有已放置实例 |

这样“托盘改日志”和“格子详情看日志”最终指向同一段内容，而完成状态只在格子详情里操作。

## 12. 回收站

### 12.1 入站

两个核心函数：

- `trashBlockDefinition(blockId)`：整个模板 + 所有 placements；
- `trashPlacement(date, segmentId)`：单条安排。

两者都会：

1. 收集 placement snapshot；
2. 写入 `state.trash`；
3. 从 blocks / assignments 移除；
4. 保存；
5. 重渲染；
6. 显示 toast。

模板删除后额外再次调用 `renderPalette()`、`renderLibrary()`、`renderTrash()`，保证托盘和工作台不残留。

### 12.2 还原

`restoreTrashEntry(entryId)`：

- 如果模板不存在，用回收记录重建；
- `findRestorableSegment` 优先使用原 segmentId，其次使用原开始/结束时间；
- 目标时间格被占用则跳过；
- 恢复 assignment 时带上 note / completed；
- 删除该回收记录；
- 保存并重渲染。

块类型可能恢复部分安排，剩余冲突会在 toast 中说明。

### 12.3 清空

`clearTrashWithConfirm` 需要二次确认，永久清空回收站。

## 13. 当日待办抽屉

### 13.1 位置与状态

- 顶栏按钮 `#todayButton`；
- 抽屉 `#todayPanel` 是 topbar 内的绝对定位下拉层；
- 打开时 `todayPanelOpen = true`；
- `todoDate` 是模块级变量：
  - 每次刷新初始化为真实今天；
  - 切换日期只在当前页面会话内有效；
  - 不写入 state；
  - 超出允许日期范围时回落到 `DATE_MIN`。

### 13.2 打开/关闭

- `openTodayPanel(date)`：校验昵称、设置日期、渲染、解除 hidden、更新 aria；
- `closeTodayPanel()`：隐藏并恢复 aria；
- 点击顶栏按钮切换；
- 点击抽屉外部、Esc、关闭按钮均收起；
- 打开日历、个人信息、复用上周时也会主动关闭抽屉，避免层叠。

### 13.3 数据来源

```text
getScheduleItemsForDate(date)
  → 从 state.days[date].segments + assignments 组出日程列表
getTodoList(date)
  → 从 state.todos[date] 取小事
getTodayPanelStats(date)
  → 汇总完成数、总数、未完成数
```

### 13.4 渲染

`renderTodayPanel()` 生成：

- 日期输入框、前后一天、今天按钮；
- 进度条和 `已完成 x / y`；
- 日程列表，带勾选、标题、时间、是否有记录；
- 小事纸条，带自动颜色、勾选、删除；
- 空状态；
- 底部的小字提示。

日程和小事分别显示 `已完成 / 总数`。

### 13.5 交互

- `handleTodoSubmit`：新增小事，自动取色，保存并重渲染；
- `toggleCustomTodo`：切换小事完成，保存并刷新统计；
- `deleteCustomTodo`：直接删除；
- `toggleScheduleFromToday`：切换日程完成，保存并同步周计划；
- `openScheduleFromToday`：收起抽屉，延迟 60ms 打开详情，避免 dialog 层叠；
- 切换日期会清空输入框草稿，防止把文字误加到另一天。

### 13.6 统计联动

`renderProfile()` 的总待办和已完成包含：

```text
countAllAssignments() + countAllCustomTodos()
countCompletedAssignments() + countCompletedCustomTodos()
```

注意这里的统计是**所有日期**，不是当前抽屉日期。

### 13.7 与 22:00 提醒联动

`getLateUnfinishedItems()` 会把今天未完成的时间轴日程和今天未完成的小事一起返回；点击小事提醒项会打开抽屉并高亮对应纸条。

## 14. 复用上周

### 14.1 计划生成

`buildReusePlan(onlyUnfinished)`：

- 取当前查看周的上一周；
- 过滤日期范围；
- 收集有模板的 assignment；
- 统计总/完成/未完成；
- 对每条来源安排：
  - 目标日期 = 来源日期 + 7 天；
  - 在目标日时间轴中找**开始/结束完全一致**的时间段；
  - 找不到则退化为只匹配开始时间；
  - 再找不到就标记为跳过；
  - 目标时间格已被占用也跳过；
  - 用 `plannedTargets` 防止同一目标重复。

### 14.2 弹出确认

`openReuseDialog` 打开 `.reuse-dialog`，提供：

- 「仅顺延未完成日程」复选框；
- 上周统计；
- 预计带入 / 跳过数量；
- 没有可带入项时禁用确认。

### 14.3 应用

`applyReusePlan`：

- 为每个计划项在目标时间格新建 assignment；
- 已完成的来源项目标记为新待办（`completed: false`），日志清空；
- 未完成项目保留 note，仍为未完成；
- 目标格已有安排则跳过；
- 保存、关闭、重渲染、toast 汇总。

### 14.4 边界

- 当前周已经是最早的允许周时按钮禁用；
- 时间轴不一致会跳过；
- 不复制自定义小事；
- 不复制时间轴本身，只按时间匹配现有目标时间轴。

## 15. 22:00 未完成提醒

### 15.1 触发条件

`maybeShowLateReminder()`：

- 当前小时 >= 22；
- 已有昵称；
- 没有已打开的 `<dialog>`；
- 当前没有聚焦在 input / textarea / select；
- 今天至少有一条未完成日程或小事。

### 15.2 触发时机

- 页面初始化后延迟 850ms 检查一次；
- 昵称首次设置完成后延迟 700ms 检查一次；
- `scheduleLateReminderCheck()` 计算到当天 22:00 的毫秒数；若已过 22:00 则安排到次日 22:00；
- 计时器触发后再次检查并重新排程。

### 15.3 内容

- 日程条目：标题、时间、日期；点击打开详情；
- 小事条目：文字、「小事 · 今天还没完成」；点击打开今天的当日待办并闪烁对应纸条；
- 标题固定为「你似乎忘了这些事：」；
- 副标题显示总未完成数。

提醒不写入持久状态，因此同一天刷新后再次进入仍可能再次提醒。

## 18. 时间轴编辑器

### 18.1 打开

`openTimelineEditor(date)`：

- 把当日 segments 深拷贝为 `timelineDraft`；
- 设置标题和快速生成默认值；
- 渲染草稿表格；
- 打开 dialog。

### 18.2 编辑

- 输入变化实时更新 `timelineDraft`；
- 增加/删除时间段；
- `generateTimeline` 按起止时间和步长生成；
- 保留开始时间相同的旧段落 ID 和高度；
- `validateTimelineDraft` 校验：

- 应用到本周其它日期；
- 开始时间相同的目标安排保留；
- 时间轴不一致或格位冲突的安排可能丢失；
- 确认后 `commitTimeline(sorted, true)`。

### 18.4 提交

`commitTimeline`：

- 当前日 segments 更新；
- 按新 segment ID 过滤 assignments；
- 应用到其它天时，按目标日原有开始时间复用 segment ID；
- 保存、关闭、重渲染。

## 24. 长期备忘模块

### 24.1 模块定位

长期备忘独立于周计划，存放在 `state.memos`，不参与每日完成率、22:00 提醒和复用上周。它适合：

- 学习网址、文档入口；
- 长期备赛 / 考证目标；
- 与某个日志块配套的参考链接；
- 一时不想拆进具体日期的长期事项。

界面由两部分组成：

1. 固定在页面底部的 `.memo-ticker` 滚动提示栏；
2. 点击提示栏打开的 `#memoDialog` 备忘管理器。

提示栏使用 `position: fixed`，左右宽度与 `.app-shell` 内容区对齐；`.app-shell` 通过底部 `padding` 预留空间，避免遮住页面最后一屏。这样它不会再和顶部信息栏、当日待办、日历等顶部浮层挤在一起。

### 24.2 提示栏结构

```html
<section class="memo-module">
  <button id="memoTicker">
    <span class="memo-ticker-label">长期备忘</span>
    <span class="memo-ticker-viewport">
      <span class="memo-ticker-line" id="memoTickerLineA"></span>
      <span class="memo-ticker-line is-next" id="memoTickerLineB"></span>
    </span>
    <span class="memo-ticker-count">3 条</span>
  </button>
</section>
```

- 提示栏固定在视口底部，是一整个按钮，点击任意位置打开管理器；
- 没有数据时显示“还没有长期备忘……”；
- 内容显示 `备忘/网址` 类型、标题，以及描述摘要或网址域名；
- 计数显示备忘总数；
- 移动端隐藏摘要，只保留类型、标题、计数和箭头。

### 24.3 双行上下滑动

`renderMemoTicker` 将内容放在 A 行，B 行作为下方待进入行。

`animateMemoTicker`：

1. 把新内容写入当前隐藏的行；
2. 强制 reflow；
3. 给旧行加 `.is-up`，向上滑出；
4. 移除新行的 `.is-next`，从下方滑入；
5. 480ms 后清空旧行、交换活动行。

CSS 过渡：

```css
.memo-ticker-line { transform: translateY(0); opacity: 1; }
.memo-ticker-line.is-next { transform: translateY(112%); opacity: 0; }
.memo-ticker-line.is-up { transform: translateY(-112%); opacity: 0; }
```

A/B 两行避免内容切换时出现空白。

### 24.4 加权随机

`pickWeightedMemo()`：

```js
const total = state.memos.reduce((sum, memo) => sum + memo.weight, 0);
let ticket = Math.random() * total;
for (const memo of state.memos) {
  ticket -= memo.weight;
  if (ticket < 0) return memo;
}
```

- 权重 1—10，概率严格按 `weight / 总权重`；
- 不使用“避免连续重复”的排除，否则会扭曲权重；
- 权重高更容易出现，但不是固定次数或固定顺序；
- 随机可能连续抽中同一条，这是预期行为；
- 只有一条备忘时不启动定时器，避免无意义轮播；
- 间隔是 `MEMO_TICKER_INTERVAL = 5600ms`。

### 24.5 轮播暂停与恢复

- 点击提示栏打开管理器时 `stopMemoTicker()`；
- `#memoDialog` 的 `close` 事件调用 `startMemoTicker()`；
- 鼠标悬停提示栏时暂停，移出后恢复；
- 定时器每次触发前检查 `document.hidden` 和 `els.memoDialog.open`；
- 保存 / 删除备忘后重新渲染提示栏并重启轮播；
- 页面标签隐藏时不会强行切换，回到页面后继续。

### 24.6 管理器布局

`#memoDialog` 是原生 `<dialog>`，内容分两栏：

```text
memo-dialog
  dialog-head
  memo-dialog-body（CSS Grid）
    memo-list-pane
      memo-list-head（计数 + 新建）
      memo-list（条目）
    memo-editor-pane
      memo-editor-head（标题 + 纯文本/网址）
      memo-form（名称、开关、URL/描述、权重、操作）
```

- 桌面：左列表 282px，右侧编辑；
- 720px 以下：上下堆叠，列表限高，编辑器展开；
- 列表按权重降序、同权重按更新时间降序；
- 列表项显示权重数字、标题、域名或描述摘要、文本/链接类型。

### 24.7 编辑表单

| 字段 | 行为 |
| --- | --- |
| 名称 | 必填，最长 80 字 |
| 直连网址 | 开关；开启后显示 URL，关闭后显示描述 |
| 网址 | 只接受 http/https；自动补 `https://`；要求有效主机名 |
| 描述 | 纯文本，最长 2000 字 |
| 权重 | range + number 同步，1—10 整数 |

- `updateMemoEditorMode()` 根据开关切换字段与右上角“纯文本/网址”标签；
- `updateMemoOpenLink()` 实时校验 URL，合法时显示「打开」链接，非法时隐藏；
- URL 校验函数 `normalizeHttpUrl` 拒绝空白、非 http/https、空主机、无点主机名；
- 保存时再次校验，错误显示在 `#memoError`；
- `linkMode` 关闭时仍可保留已填 URL，方便以后重新打开；
- 保存成功不关闭弹窗，方便继续维护；提示栏在后台刷新，关闭弹窗后恢复轮播。

### 24.8 删除与数据边界

- 删除通过 `askConfirm` 二次确认；
- 删除后不进回收站，无法恢复；
- 删除当前条目后自动选中剩余备忘中的一条，没有剩余则进入新建表单；
- 最多 100 条；
- 清空全部数据会清空 `memos`，但保留昵称和打卡；
- 导出备份、导入备份都包含 `memos`；
- 旧备份没有 `memos` 字段时归一化为空数组，不报错。

### 24.9 安全性

- 标题、描述、域名都经过 `esc()` 后才拼接进 HTML；
- URL 只允许 http/https，阻断 `javascript:`、`file://` 等协议；
- 外部链接使用 `target="_blank"` 和 `rel="noopener noreferrer"`；
- 所有数据只在本机 localStorage，不上传。

## 25. 限制、边界与扩展建议

### 25.1 已知限制

- 纯 localStorage：换浏览器/换电脑/清站点数据会丢失，需要导出备份；
- 没有后台，22:00 提醒只在页面打开或进入时生效；
- 时间轴结束必须晚于开始，不支持跨午夜；
- 一个时间格最多一个日程；
- 小纸条只支持纯文本；
- 复用上周只复用日程，不含自定义小事；
- 日历圆点不显示小事；
- 删除小事直接生效，不进回收站；
- 无全局撤销栈；
- 托盘日志描述是批量同步语义：从表格单独编辑一条后，不会自动同步到其它实例，需再次从托盘保存；
- 长期备忘轮播是概率性的，权重高不代表固定出现次数，可能连续重复同一条；
- 长期备忘最多 100 条，删除不进回收站；
- 长期备忘网址只支持 http/https，不支持本地文件协议；
- 大文本/长期数据可能触及 localStorage 容量限制。

### 25.2 扩展时的优先检查点

1. 新字段是否同时加入 createInitialState、normalizeState、clearAllData；
2. 新交互是否修改 state 后调用 saveState；
3. 新 DOM 是否加入 `cacheElements`；
4. 新列表是否使用 `esc()`；
5. 是否影响 `renderAll` 顺序；
6. 是否需要在移动端 720/480 断点补样式；
7. 是否影响首次昵称、打卡、22:00 提醒等联动；
8. 是否更新维护指南、全量解读和预览图（如项目提供）。

### 25.3 推荐的下一步扩展

- 自定义小事支持时间或标签；
- 周模板 / 每周重复日程；
- 周复盘统计与完成率；
- 打印 / PDF 导出；
- 备份提醒（距上次导出超过 N 天提示）；
- 搜索/过滤日程块；
- 长期备忘支持分类、排序、置顶和提醒时间；
- 子任务清单；
- 撤销栈。
